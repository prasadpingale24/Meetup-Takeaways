# Meetups

A collection of notes, recaps, and supporting materials from technical community meetups. Content is organized by community or chapter; each folder holds materials for one or more events.

## What you will find here

Meetup materials in this repo typically follow a recap-oriented structure:

| Section | Purpose |
| -------- | -------- |
| **Event or theme overview** | Context for the main topic (e.g. a conference, product launch, or workshop theme), including dates, highlights, and why it matters to the audience. |
| **Community** | Short description of the user group, meetup chapter, or organizers—their mission, reach, and how they serve the local tech community. |
| **Speakers** | Brief bios for presenters: roles, expertise, community involvement, and relevant credentials. |
| **Sessions** | Per-talk or per-segment notes: themes, bullet-point takeaways, announcements, and demos—often grouped by service area or topic (e.g. AI, storage, security). |
| **Derivatives** | Optional companion formats (e.g. infographic outlines or social-ready summaries) distilled from the full recap. |

Not every document includes every section; shorter events may only have session notes.

## Repository layout

```
Meetups/
├── README.md                 # This file
└── <CommunityOrChapter>/     # One folder per group (e.g. a user group or city chapter)
    ├── <Event-Recap>.md      # Full recap: overview, community, speakers, sessions
    └── <Event>-<variant>.md  # Optional: infographic, one-pager, etc.
```

- **Community folders** use a clear name (often the official group name).
- **Recap files** use descriptive titles: event name, theme, and location or date when helpful.
- **Variants** share the same event but target a different format or audience (e.g. visual outline vs. long-form notes).

## Conventions for recap documents

When adding or editing a recap, these patterns keep material consistent and easy to scan:

1. **Title** — Event or session series name and the hosting community.
2. **About the event** — What happened, when, and headline themes (bullets work well for launches and keynotes).
3. **About the community** — Who organized it and what the group does (keep it factual and welcoming).
4. **About the speakers** — One subsection per speaker with a short bio.
5. **Sessions** — `## Session N: Speaker Name` (or talk title), then topic headings and bullet takeaways.
6. **Footer or disclaimer** — Optional note that the recap is not exhaustive (conferences especially).

Use standard Markdown: headings, lists, and **bold** for names and product terms. Link to official docs or event pages when URLs are stable.

## Contributing

1. Create or use the folder for your community or chapter.
2. Add a new `.md` file for the event recap (and optional variant files).
3. Prefer plain text and Markdown; avoid embedding secrets, unreleased URLs, or personal contact details unless intended for publication.
4. Keep speaker bios respectful and accurate; update them if someone requests a correction.
